### 2.2 本地 Agent：Perplexity Portable Computer 登陆 Windows RTX

**标签**：`本地部署` `Agent` `硬件` `NVIDIA RTX`  
**重要性**：高

NVIDIA 9 月 14 日宣布 Perplexity Portable Computer 已在兼容 NVIDIA GeForce RTX PC 和 RTX PRO Workstation 的 Windows 版本中提供。

它的意义不在于又多了一个本地聊天 UI，而在于它采用 **local-first Agent** 模式：

- 本地模型执行文件分析与多步工作；
- 敏感数据可以保留在设备端；
- 本地完成的任务不消耗 Perplexity Computer 云端 credits；
- 更复杂的研究/推理任务可以再编排到云模型。

这进一步验证了一个值得长期追踪的架构方向：**本地小/中模型负责隐私数据、工具调用和高频任务，云端强模型负责困难推理**。

来源：
- https://blogs.nvidia.com/blog/local-ai-perplexity-windows-pcs/

### 2.5 MCP：2026-07-28 仍是协议基线，兼容性风险值得继续盯

**标签**：`MCP` `Protocol` `Agent`  
**重要性**：中

本周没有新的正式 MCP specification。当前 `2026-07-28` 相比旧版最关键的变化仍包括：

- 移除 protocol-level sessions 和 `Mcp-Session-Id`；
- 移除 `initialize` / `notifications/initialized` handshake；
- protocol version 与 capabilities 随每个 request 通过 `_meta` 携带；
- 服务端需要跨调用状态时，改用显式 state handles。

这意味着 Java / Spring AI MCP 项目后续升级 SDK 时，**双版本兼容和协议协商**比新增工具 API 本身更值得测试。

来源：
- https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/2026-07-28/changelog.mdx

## 4. 关键技术细节

### 4.1 本地 Agent 的价值开始从 tok/s 转向“任务吞吐”

传统本地 LLM benchmark 主要比较 generation tok/s；但 Portable Computer、PAIR 一类系统更应该看：

- 多 Agent 并发任务完成时间；
- 本地/云模型路由策略；
- 文件与隐私数据是否离机；
- 工具调用延迟；
- 多机器资源调度效率。

因此以后评估 RTX Spark、Mac、DGX Spark 或 4070 Ti Super，不应只比较单请求 tok/s。

### 4.2 Codex 模型退役会影响“隐藏的固定配置”

模型迁移最容易漏掉的不是 CLI 当前会话，而是仓库脚本、workspace defaults、自定义 Agent 和 scheduled automation。建议把模型 ID 视作可配置项，并在项目文档中记录推荐模型，而不是散落硬编码。

### 4.3 MCP stateless 化对权限系统也有影响

如果 MCP 权限判断过去隐式依赖 session 身份/状态，2026-07-28 的 stateless 设计意味着权限上下文需要更明确地来自认证层、request metadata 或显式 state handle。对于“工具路径 + 用户/角色授权”这类服务端权限设计，这是值得提前验证的兼容点。

## 5. 对现有技术方案可能产生的影响

### Java / Spring AI

本周建议仍是 **保持当前稳定版本，不为了追新而升级**。重点测试 MCP 新旧协议兼容、OpenAI-compatible reasoning/tool-call 映射和 streaming 行为。

### Codex / AI Coding

如果内部 AI Coding 产品或自动化脚本依赖 GPT-5.5，应在 10 月 14 日前完成 `gpt-5.6-sol` 验证。建议至少回归：代码生成、长任务、tool/MCP 调用、上下文压缩和测试执行。

### 4070 Ti Super + Qwen3.8-27B

llama.cpp 一周推进很快，但目前没有足够证据表明本周 build 对该 CUDA 配置存在必须升级的显著收益。继续使用稳定 build，等出现明确 CUDA/Qwen 性能改动后再 A/B benchmark 更划算。

### 本地 LLM 硬件选择

本地 Agent + 混合云正在变成比“单机最大能塞多大模型”更重要的变量。后续比较 Mac / RTX PC / DGX Spark / RTX Spark 时，应增加 **多 Agent 并发、局域网协同、OpenAI-compatible endpoint、功耗/任务** 等指标。
