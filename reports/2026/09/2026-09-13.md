本周最值得关注的增量主要集中在 **Codex 工具链快速迭代** 与 **llama.cpp 对 Vulkan/Qwen 推理路径的连续优化**。

- **llama.cpp**：9 月 10～13 日连续发布多个构建，Vulkan 后端出现针对 **Qwen 小 M 矩阵乘法、MoE prefill、异步张量复制和 argsort** 的优化与修复。对于非 CUDA 本地推理，尤其是 Vulkan 路径，这是本周最直接可落地的性能信号。
- **Spring AI / Spring AI Agent**：过去 7 天未发现新的正式 Spring AI 稳定版发布。当前稳定版本仍为 `2.0.1`，主线 `2.x` 面向 Spring Boot 4.x。Agent Skills / agent-utils / A2A 等 Agent 能力仍主要分布在 Spring AI Community 与配套项目中，本周没有出现需要立即迁移的官方架构变化。
- **MCP**：本周未发布新的协议版本。当前正式规范仍为 `2026-07-28`，8 月路线图中的重点仍是 agentic messaging、HTTP-native transport、Agent Identity / enterprise security、primitives 与 SDK DX。对于 Spring AI 项目，近期重点不是“追新协议版本”，而是评估 2026-07-28 的 breaking changes 与 SDK 实际支持程度。
- **Qwen**：过去 7 天未发现新的 Qwen 官方开放权重主版本。`Qwen3.8-27B` 仍是当前非常值得关注的本地模型；但 llama.cpp 本周针对 Qwen 的 Vulkan 优化，使它的本地部署体验继续改善。
- **本地硬件**：本周窗口内未发现比前一周 NVIDIA RTX Spark / PAIR 发布更重大的官方硬件公告，因此本期不把旧消息重复列为“新增”。下一阶段更值得跟踪 RTX Spark 10 月上市后的真实功耗、显存/统一内存带宽与 llama.cpp 实测。

**标签**：`Codex` `Agent` `SDK`  
**重要性**：高

OpenAI `openai/codex` Releases 在 9 月 10 日发布 **Python SDK 0.154.0**，随后在 9 月 11 日连续出现多个 `0.155.0-alpha` 预发布版本。

### 2.2 llama.cpp：Vulkan 后端连续优化，Qwen 是直接受益对象

**标签**：`llama.cpp` `Qwen` `Vulkan` `本地部署`  
**重要性**：高

llama.cpp 在本周继续保持非常高的发布频率。最值得关注的是 9 月 10 日附近的一组 Vulkan 改动：

#### b10899 — Qwen 小矩阵优化

核心改动：

- `m=1` 的 `mul_mat` 通过交换 A/B 优化
- 改善 small-M 场景性能
- small-M 允许 `split_k`
- coopmat2 的 tile 选择不再只看 N，也考虑 M

官方 release 明确将这次改动描述为：

> `vulkan: small M matrix optimizations for qwen`

这对 Qwen 本地推理尤其值得关注，因为生成阶段大量操作属于小 batch / 小 M 场景。

#### b10900 — Vulkan MoE prefill 优化

新增 `topk_moe` fusion during prefill，目标是改善 MoE 模型在 Vulkan 后端的 prompt / prefill 性能。

#### b10901 — 空闲上下文下异步张量复制改用 CPU write

`ggml_backend_vk_cpy_tensor_async` 在 Vulkan context 空闲时允许走 CPU 写路径，以降低不必要的 GPU 调度开销。

#### b10903 — Vulkan argsort 修复

修复 large argsort 的 data race / OOB access，属于稳定性改进。

#### b10935 — 9 月 13 日最新构建

截至本期生成时，GitHub Releases 已出现 `b10935`，并继续提供 CUDA 12.4 / 13.3、Windows、Linux、macOS、Android 等预编译构建。

### 对本地部署的意义

如果主要使用 **NVIDIA + CUDA**，这些 Vulkan 改动对现有 4070 Ti Super 路径不是直接性能提升；但它们有三个重要信号：

1. llama.cpp 正持续针对 **Qwen 架构** 做专项优化；
2. Vulkan 路径的性能差距可能继续缩小，影响 AMD / Intel / 跨平台设备的可用性；
3. Qwen3.8-27B 一类模型已经成为社区优化的重点对象，后续 CUDA / speculative decoding / KV cache 优化也值得继续跟踪。

**重要性**：中

本周没有观察到 Spring AI Core 将 Skills / Deep Agent / Graph 编排正式吸收进核心的新版本事件。

当前可确认的结构仍然是：

- Spring AI Core：ChatClient、ToolCallback、Advisor、Memory、MCP 等基础抽象

- Agent：负责规划、多步调用、错误恢复与结果解释

三者更像组合关系，而不是一对一替代。

## 4. 关键技术细节

### 4.1 llama.cpp 的 small-M 优化为什么值得关注

LLM 推理分为两个非常不同的阶段：

- **Prefill**：一次处理大量 prompt token，矩阵维度较大
- **Decode / generation**：通常每步只生成 1 个或少数 token，矩阵的 M 维很小

因此 b10899 针对 `M=1` 和 small-M 的 Vulkan 优化，与生成速度的相关性通常比“大矩阵吞吐 benchmark”更高。

对于本地交互式 Agent，用户实际感受往往主要由：

- 首 token 延迟
- decode tok/s
- tool call 后重新 prefill 的成本

共同决定，而不是单独看 prompt benchmark。

### 4.2 Agent Skills 不等于 Tool Calling

Skills 的关键价值是 **progressive disclosure**：启动时只让模型看到 skill 的名称/描述，需要时再加载完整 `SKILL.md` 和相关资源。

它解决的是“如何让大量能力不把上下文撑爆”的问题。

MCP / Function Calling 解决的则是“模型如何调用外部能力”。

因此，一个更合理的 Java Agent 架构是：

```text
Agent Runtime
├── Skills        # 规则、流程、领域知识、schema 说明
├── MCP / Tools   # 实际执行数据库/API/文件操作
├── Memory        # 长短期上下文
└── Planner       # 决定何时加载 Skill、何时调用工具
```

### 4.3 MCP 2026-07-28 的 stateless 化需要谨慎对待

MCP core stateless 化后，不能简单假设老式“长连接 session + server 主动发请求”的交互模型仍然原样成立。

尤其是：

- elicitation
- sampling
- server-to-client requests
- long-running tasks

都需要结合新 extension / SDK 机制重新理解。

Spring AI 项目如果以后升级 MCP Java SDK，建议把协议兼容性测试单独纳入集成测试。

## 5. 对现有技术方案可能产生的影响

### Spring AI 项目

**本周建议：保持版本稳定，不因无关更新升级。**

如果当前工程使用 Spring AI 2.0.1，并且已经通过自定义 Jackson MixIn / 映射解决第三方 OpenAI-compatible 网关的 `reasoning` 字段问题，本周没有发现需要推翻该方案的新版本信号。

重点仍应验证：

- 实际运行时 JAR
- ChatCompletionChunk → AssistantMessage 映射
- tool call 与 reasoning 同时出现时的数据保留
- streaming / non-streaming 一致性

### 本地 Qwen3.8-27B + llama.cpp

对于 NVIDIA 4070 Ti Super：

- 本周 Vulkan 优化不是直接升级理由；CUDA 仍应作为主路径。
- 但 llama.cpp 更新频率高，建议每隔 2～4 周固定做一次 A/B benchmark，而不是每天跟最新版。
- benchmark 至少记录：build SHA、CUDA runtime、context、KV cache dtype、batch、ubatch、Flash Attention、prompt t/s、generation t/s、VRAM。

### Codex

如果使用 Codex 做 Java / Spring AI 项目开发：

- 建议把 `AGENTS.md` 放进仓库根目录；
- 对重要项目固定 Codex CLI/SDK 版本；
- 把 MCP、Skills、脚本权限写成显式项目配置；
- 对自动修改代码的任务，优先让 Codex 运行测试，而不是只生成 diff。
