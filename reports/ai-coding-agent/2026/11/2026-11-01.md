## 一、本期摘要

**最重要的三条趋势：**（1）OpenCode 2.2.x 从工具调用界面扩展到「目标驱动的持续执行、定时调度、交互产物和插件生态」，但伴随 SDK 导出、OpenTUI 和管理策略的迁移；（2）Codex 0.165–0.166 加强多会话记忆、线程分叉、审批恢复与网络诊断；（3）Claude Code 2.1.311–316 聚焦 MCP 取消、长任务恢复、文件保护、分层企业策略与预算控制。对 Engineering Agent 而言，**任务生命周期、策略隔离、可恢复执行和可验证交付**正成为一套共同基础设施。

本期未将 10 月 25 日之前已报道的 OpenCode 2.1.x、Codex 0.164 或 Claude Code 2.1.310 重复计入。Cursor 在本窗口内官方 Changelog 未显示新公告；但发现上期遗漏的 10 月 20 日 Agent SDK，列在「上期补遗」，不计入本期 10 项。

## 三、重要更新

### 1. OpenCode 2.2.0：SDK、插件契约再次迁移（P0）

**事实（10 月 27 日）：** `@opencode/ai` 根导出改为 Promise API；Effect API 改从 `@opencode/ai/effect` 导入，旧 `@opencode/ai/promise` 移除。OpenCode GitHub Action 不再发布；TUI 插件依赖 OpenTUI 0.7。插件可通过 `ctx.session.instructions.entry.put/list/remove` 维护具名的会话指令条目，变更在后续步骤增量生效，并能跨压缩与撤销保留。新增可配置的 Provider/Model Prompt Cache TTL。

**产品影响：** 2.1→2.2 不只是 UI 升级；对自研插件、SDK 包装和 GitHub Actions 流水线是潜在破坏性升级。具名指令条目可替代反复重写 system prompt，适合多阶段研发 Agent 的规则注入。

**待验证：** 用锁定依赖的工程分别构建 2.1.x/2.2.x；检查 `@opencode/ai` 导入、TUI 插件生命周期、旧 GitHub Action 工作流；对比具名指令注入前后的 prompt-cache 命中、压缩后约束保真与 token 成本。

来源：https://opencode.ai/changelog （v2.2.0）。标签：#OpenCode #BreakingChange #Plugin #PromptCache。

### 2. OpenCode 2.2.1：/goal 与实验性定时调度（P0）

**事实（10 月 29 日）：** 新增 `/goal <objective>`，会话可围绕目标持续执行，直到 reviewer 确认目标达成；支持 `/goal pause|resume|clear`。同时新增需显式开启的 `experimental.schedules`、`/schedule` 和 SDK `client.experimental.schedule.{create,list,get,pause,resume,delete}`；插件增加实验性 `experimental.idle` Session Hook。

**产品影响：** 从“单次问答驱动”走向“目标与检查点驱动”，适合需求→实现→测试→审查的长任务，但也提高了无界循环、重复执行和审批缺席的风险。目标完成必须由独立可验证的验收条件约束。

**待验证：** 设计 3 类目标（可自动验收、需人工审查、不可达），测量任务轮数、费用、停机条件；在重启、暂停/恢复、权限拒绝和资源耗尽下检查是否重复运行。

来源：https://opencode.ai/changelog （v2.2.1）。标签：#Goal #AgentLoop #Scheduling #HumanReview。

### 3. OpenCode 2.2.3：MCP、Skill、Plugin 独立策略（P0）

**事实（10 月 30 日）：** 托管策略中的 `integration.use` 现在只管集成账号；新增 `mcp.use`、`skill.use`、`plugin.use` 分别约束 MCP Server、技能和插件。旧带资源前缀规则可转换，但无前缀的 `integration.use` 不再覆盖其他三类。版本还支持将已登录的 Claude Code 作为 Claude Agent Provider 接入 OpenCode；TUI 插件进一步要求 OpenTUI 0.8。

**产品影响：** 权限域从统一“集成使用”细分为独立资源类型，企业策略迁移可能出现意外放行或误拒绝。跨 Agent 运行时复用登录态需要审查凭据和权限边界，不能等同于模型 API Provider。

**待验证：** 设计 integration/MCP/skill/plugin 四维允许、拒绝与继承矩阵；验证旧策略迁移前后等价性；测试 Claude Agent 登录态、审计 ID、会话取消和远程执行边界。

来源：https://opencode.ai/changelog （v2.2.3）。标签：#ManagedPolicy #MCP #Skill #ClaudeAgent。

### 4. OpenCode 2.2.4：交互式产物、持久终端和定时任务去重（P1）

**事实（10 月 30 日）：** 开启 `experimental.artifacts` 后，Agent 可用 `artifact_create/read/update/delete` 发布 HTML 或静态交互产物，支持内置本地 Provider 或插件存储；Desktop 终端归属会话，重启后保留滚动历史并与 TUI 同步。启用的实验性 Schedule 可在 `opencode serve` 下运行，多个 Server 进程之间会协调，避免同一计划重复触发。

**产品影响：** Engineering Agent 的交付物可从 PR 扩展到可交互原型、测试报告和验收页面。定时触发去重解决了调度层的重复启动，但**不能**替代工具执行层的业务幂等。

**待验证：** 将“需求→原型 HTML→自动测试→审查链接”作为端到端案例；检查 artifact 访问控制、清理、XSS/内容隔离；启动双 Server，验证调度去重、失败重试和重启恢复。

来源：https://opencode.ai/changelog （v2.2.4）。标签：#Artifacts #PersistentPTY #Schedules #Idempotency。

### 5. OpenCode 2.2.5：上下文预算与 MCP 大消息（P1）

**事实（10 月 30 日）：** `compaction.buffer` 可配置为上下文窗口比例（例如 `"20%"`），而不只是固定 token。修复 stdio MCP 消息超过 10 MiB 时断线的问题，改善大消息读取性能；LiteLLM 的上下文超限可触发压缩；模型切换或恢复被中断响应时不再把 reasoning 误当普通文本。

**产品影响：** 混用不同上下文窗口模型时，按比例预留更易维护；大体积工具返回与 reasoning_content 的结构保真直接影响渐进式工具加载和会话恢复。

**待验证：** 用小/大上下文模型测试 10%、20%、固定 token 预留；模拟 1/10/20 MiB MCP 响应；对比模型切换、reasoning 分片、恢复时消息结构和压缩后任务成功率。

来源：https://opencode.ai/changelog （v2.2.5）。标签：#ContextWindow #MCP #Reasoning #Compaction。

### 6. Codex CLI 0.165.0：Memory v2、线程分叉与取消语义（P0）

**事实（GitHub 10 月 27 日 UTC、北京时间 10 月 28 日）：** 新配置档案默认启用 Memory v2，并支持导入外部 Agent 的记忆；App Server 新增实验性的 attached thread forks；会话选择器支持仓库筛选。修复远程 MCP 工具响应 Future 被丢弃后请求未取消、计划模式切换或中断后排队消息意外重启任务，以及新会话未遵守服务端默认审批 reviewer 的问题。新增内置 Google Cloud Vertex AI Provider。

**产品影响：** 长期研发 Agent 的记忆层、会话树和取消传播开始形成明确运行时语义；需要区分可共享记忆、项目私有记忆与单线程状态，避免跨项目污染。

**待验证：** 跨两个仓库导入同名记忆并测试隔离；线程 fork 后分别修改权限；在 MCP 工具执行期间中断并确认远端取消；模拟排队提示和 Plan 切换。

来源：https://github.com/openai/codex/releases/tag/rust-v0.165.0 。标签：#Codex #Memory #ThreadFork #MCP。

### 7. Codex CLI 0.166.0：队列恢复、网络诊断与审批一致性（P0）

**事实（GitHub 10 月 29 日 UTC、北京时间 10 月 30 日）：** 新增 `codex queue --resume`，可在排队消息后恢复已卸载线程；新增 `codex doctor --network-only`，针对连接配置、网络和 WebSocket 排障。修复恢复或 fork 时已确认的审批/权限设置丢失、父线程解除归档时子线程未恢复、App Server 线程启动/关闭竞态，以及恢复时 reasoning token 统计丢失导致过早压缩。

**产品影响：** 可恢复执行需要把队列、审批、子线程、token 账本视为一致的任务状态。网络诊断命令有利于远程开发机和企业代理环境排查。

**待验证：** 创建父子线程、排队后卸载/恢复；对比恢复前后权限快照和 token 计数；通过断网、WebSocket 断开、代理失败验证 doctor 输出及重连行为。

来源：https://github.com/openai/codex/releases/tag/rust-v0.166.0 。标签：#Codex #Resume #Approval #NetworkDiagnostics。

### 8. Claude Code 2.1.311：MCP 中断与子 Agent 工作树保护（P0）

**事实（GitHub 10 月 26 日 UTC、北京时间 10 月 27 日）：** 修复读取 MCP Resource 或下载 Skill 时用户中断迟迟不生效；修复子 Agent 启动后才连接成功的 MCP Server 工具不可用；修复后台子 Agent 仍在工作时其隔离 Worktree 被提前删除。还修复压缩后读取旧 MEMORY.md/CLAUDE.md、Headless/SDK 会话消息顺序异常，以及超过 200K token 时错误要求 1M Context Credits 而非压缩。

**产品影响：** ToolSearch 的检索准确率之外，还要覆盖 MCP 动态连接、取消传播、资源清理顺序和压缩后的上下文一致性。孤儿任务和工作树提前回收会导致隐蔽的数据损失。

**待验证：** 启动后延迟接入 MCP Server；在资源读取期间取消；让子 Agent 创建后台子任务再结束父任务；修改 CLAUDE.md 后触发压缩并核对最新规则。

来源：https://github.com/anthropics/claude-code/releases/tag/v2.1.311 。标签：#ClaudeCode #MCP #Subagent #Worktree。

### 9. Claude Code 2.1.314：写保护与 ToolSearch 网关降级（P0）

**事实（10 月 30 日）：** 新增 `permissions.blockWritesOutsideWorkingDirectories`，在各种权限模式下阻止 Write/Edit/NotebookEdit 写入工作目录外。网关不接受 ToolSearch `tool_reference` 块时，改为不带 ToolSearch 重试一次并记住降级状态。VS Code 与 Desktop Code Tab 新增空闲压缩；修复 `claude -p` 启动失败却返回 0、MCP 可匿名使用却显示需登录，以及管理员模型 effort 上限导致持续错误。

**产品影响：** 目录级写保护可以补强工具权限，但需验证 shell、符号链接和其他写入路径是否受相同策略覆盖。ToolSearch 降级必须被观测，否则可能悄然改变 token、召回和费用。

**待验证：** 跨工作目录 Write/Edit/NotebookEdit、shell 重定向和符号链接；拒绝 tool_reference 的兼容网关；长会话空闲压缩；CI 中检查 `claude -p` 失败退出码。

来源：https://github.com/anthropics/claude-code/releases/tag/v2.1.314 。标签：#Sandbox #ToolSearch #Gateway #Headless。

### 10. Claude Code 2.1.316：企业分层策略与团队预算（P0）

**事实（10 月 31 日）：** Claude apps gateway 增加 `managed.policy_mode: layered`，可合并多个匹配开发者的策略；增加团队共享月预算 `pooled_budget` 和子 Agent 默认 effort 配置 `CLAUDE_CODE_SUBAGENT_EFFORT`。修复网关未对请求中所有模型字段执行 available/denied 模型准入、`--restricted` 会话在特定 Read allow 规则下上传工作目录外文件，以及恢复 Worktree 时沙箱未正确生效等安全边界问题。

**产品影响：** 多团队、多项目、多模型的权限策略应有明确合并顺序和拒绝优先级；共享预算需要与任务/子 Agent 的成本归属结合。模型白名单要覆盖请求中的每一个模型字段，不能只校验主模型。

**待验证：** 用组织/团队/项目三层冲突策略验证最终决策；预算耗尽后主/子 Agent 的停机与降级；测试 `--restricted` 文件外传、恢复工作树的沙箱，以及多模型字段拒绝。

来源：https://github.com/anthropics/claude-code/releases/tag/v2.1.316 。标签：#Enterprise #Policy #Budget #Sandbox。

## 五、产品定位与架构启示

**定位建议：** AI Engineering Agent 的差异化正从“更聪明地写代码”转向“以可验证目标持续交付”。建议将内部系统划分为：Goal/Task Orchestrator、Tool Registry/Search、Policy Engine、Execution Sandbox/Worktree、Memory/Context Manager、Artifact/Eval Store 和 Observability/Cost Accounting 七层。所有工具执行都要具备任务 ID、权限判定、是否幂等、可否取消、产物指纹和失败恢复记录。

**优先级排序：** P0 首先处理 OpenCode 2.2.x 插件/策略兼容、跨目录写保护与多层策略、长任务取消/恢复；P1 验证 /goal、Schedule、Artifact、Memory v2；P2 再考虑统一多种 Agent Runtime 的适配层。不要直接把实验性功能当作稳定生产接口。

## 六、推荐的可复现实验

| 优先级 | 实验 | 对照设计 | 观测指标 |
|---|---|---|---|
| P0 | OpenCode 2.1→2.2 插件与策略回归 | 旧/新 SDK import、OpenTUI 0.6/0.7/0.8、旧/新管理策略 | 编译失败数、权限误放行数、工具调用成功率 |
| P0 | Goal Loop + Schedule 幂等 | 单进程/双服务端、人工确认/自动验收、断线重启 | 重复触发数、完成率、循环轮数、token 成本 |
| P0 | ToolSearch/MCP 取消与恢复 | 42 工具基准，延迟连接/断线/取消/大响应 | Recall@3、任务成功率、重复副作用、P50/P95 |
| P0 | 多层策略与工作树写保护 | 组织/项目冲突、symlink、shell、fork/resume | 越权成功数（目标 0）、误拒绝率、审计覆盖率 |
| P1 | Agent 交互产物 + Eval | 需求→HTML 原型→测试→PR，对照纯代码输出 | 交付周期、验收通过率、产物可复现率 |

**优先复现：**（1）OpenCode 2.2 插件/策略回归，避免升级造成隐性权限变化；（2）42 工具 ToolSearch + MCP 取消/恢复/大响应组合实验，可复用既有 Lucene/Jev 检索基准；（3）Goal + Schedule 的双服务端幂等与成本上限。
