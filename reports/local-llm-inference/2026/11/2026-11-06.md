# 本地 LLM 推理研究深度简报｜2026-11-06

**证据**：A=上游发布；B=论文作者测试；C=第三方问题报告；D=开放 PR/待验证。P0=优先回归，P1=条件验证，P2=储备。本期**没有在用户设备上运行实验**；未知值记 NA。开放 PR 不等于已合并。

## 一、执行摘要与已有基线

本周最有实际价值的是 llama.cpp v0.9.0 的版本回归、Qwen MTP 与 Blackwell CUDA 的开放优化提案、server 多模态/并发稳定性问题，以及 MLX VLM 正确性和 ComfyUI 视频内存路径。高质量的同机端到端新性能数据较少，**不把开放 PR 当成确定收益**。

历史基线（不是本周实测）：RTX 4070 Ti Super 16GB、Ubuntu 22.04、Qwen3.8-27B IQ4_XS，-ngl 999 -c 6144/7168 -fa on -b 2048，K/V q8_0；pp 228–240 tok/s，tg 34.1–34.5 tok/s，VRAM 约 14.75 GiB；8192 ctx 曾 OOM。DGX Spark/GB10 为 ARM64 CUDA 128GB；Mac Apple Silicon 仅作为兼容性对比，不假定拥有具体设备。

## 三、逐项研究

### 1. llama.cpp v0.9.0 版本回归

**来源/日期**：[原始记录](https://github.com/ggml-org/llama.cpp/releases/tag/v0.9.0)，2026-11-04；**证据及优先级**：A/P0。

**核心结论**：新版本发布，需核对 CUDA、server API 与 GGUF 兼容；版本号本身不是加速证明。

**硬件适用性及限制**：4070/GB10 CUDA、Mac Metal 分别构建；旧服务保留。

**复现实验（环境、参数、基线、指标）**：固定 Qwen3.8-27B IQ4_XS、-c6144/7168、q8_0 K/V、-fa on，旧版对 v0.9.0；llama-bench -p 512 -n 128 -r 5，测 pp/tg、TTFT、p95、VRAM、SSE/tool_calls。

**实测对比与应用判断**：无同机对照，NA；优先回归。

### 2. Qwen MTP KV-only graph 提案

**来源/日期**：[原始记录](https://github.com/ggml-org/llama.cpp/pull/31750)，2026-11-05；**证据及优先级**：D/P1。

**核心结论**：用 KV-only graph 优化草稿 catch-up 的开放 PR；不能视为已合并。

**硬件适用性及限制**：GB10 的 Qwen MTP 优先；4070 dense 模型不直接受益。

**复现实验（环境、参数、基线、指标）**：独立 PR 工作树、同 GGUF/草稿权重/seed，draft on/off，测接受率、tg、RSS、正确性、TTFT。

**实测对比与应用判断**：未核实 GB10 实测，NA。

### 3. Blackwell MXFP4 W4A8 CUDA kernel 提案

**来源/日期**：[原始记录](https://github.com/ggml-org/llama.cpp/pull/31747)，2026-11-05；**证据及优先级**：D/P1。

**核心结论**：尝试使用 Blackwell mxf8f6f4 MMA；尚未证明端到端性能收益。

**硬件适用性及限制**：GB10 需验证 dispatch；4070 Ada 不具备同代指令。

**复现实验（环境、参数、基线、指标）**：先 backend ops，再 MXFP4 模型 pp512/2048、tg128、kernel profiler、输出误差。

**实测对比与应用判断**：无 GB10 端到端数据，NA。

### 4. Qwen-VL cache reuse 风险

**来源/日期**：[原始记录](https://github.com/ggml-org/llama.cpp/issues/31704)，2026-11-05；**证据及优先级**：C/P0。

**核心结论**：报告多模态 cache_reuse 被禁用，属于未确认问题。

**硬件适用性及限制**：4070/GB10 的多模态服务；Mac 视后端。

**复现实验（环境、参数、基线、指标）**：同图+同文本重复 20 次，对比 cache hit、TTFT、VRAM、输出一致性。

**实测对比与应用判断**：无可靠吞吐对照，NA。

### 5. 长 embedding 取消后资源未释放

**来源/日期**：[原始记录](https://github.com/ggml-org/llama.cpp/issues/31710)，2026-11-05；**证据及优先级**：C/P0。

**核心结论**：问题报告称取消后服务不能继续处理请求，/health 仍为 ok；未确认普遍性。

**硬件适用性及限制**：4070 16GB 尤需关注服务可靠性。

**复现实验（环境、参数、基线、指标）**：长 embedding 请求中途取消，再发 20 次短请求；测 slot、RSS、VRAM、成功率、health。

**实测对比与应用判断**：无性能数字；价值在正确性。

### 6. CUDA 非统一 KV 并发碎片报告

**来源/日期**：[原始记录](https://github.com/ggml-org/llama.cpp/issues/31756)，2026-11-05；**证据及优先级**：C/P1。

**核心结论**：32 个变长请求下可能出现内存碎片，属于问题报告。

**硬件适用性及限制**：GB10 可复现 32 slots；4070 从 1/2/4 并发渐进测试。

**复现实验（环境、参数、基线、指标）**：256/1024/4096 混合 prompt，-np 1/2/4/8/32，测 OOM、reserved/allocated、p95、总 tok/s。

**实测对比与应用判断**：无已核实本机数值。

### 7. MLX sliding-window suffix prefill 提案

**来源/日期**：[原始记录](https://github.com/ml-explore/mlx-lm/pull/2030)，2026-11-02；**证据及优先级**：D/P1。

**核心结论**：尝试复用前缀，仅 prefill suffix；需验证 SWA 正确性。

**硬件适用性及限制**：仅 Apple Silicon MLX。

**复现实验（环境、参数、基线、指标）**：固定支持 SWA 模型，4K/16K 前缀、128/512/2048 suffix，比较 TTFT、pp、内存、输出 hash。

**实测对比与应用判断**：尚无可靠端到端数字。

### 8. MLX 超长 prompt 防挂起

**来源/日期**：[原始记录](https://github.com/ml-explore/mlx-lm/pull/2034)，2026-11-04；**证据及优先级**：D/P1。

**核心结论**：开放 PR 拟把超过模型上下文的挂起改为明确报错；属于可靠性修复。

**硬件适用性及限制**：Mac MLX，非 CUDA 路径。

**复现实验（环境、参数、基线、指标）**：上下文上限前后各 1 token，比较错误码、响应时间、后续请求可用性。

**实测对比与应用判断**：非性能加速。

### 9. MLX Qwen35 VLM YaRN RoPE 修复提案

**来源/日期**：[原始记录](https://github.com/ml-explore/mlx-swift-lm/pull/761)，2026-11-02；**证据及优先级**：D/P1。

**核心结论**：提议按 rope_parameters 正确应用 YaRN；不等于 OCR 速度提升。

**硬件适用性及限制**：Mac VLM；GB10/4070 可作为质量参考。

**复现实验（环境、参数、基线、指标）**：20 张图含竖排日文 OCR，固定图像尺寸，比较 CER/WER、TTFT、峰值内存。

**实测对比与应用判断**：无同机实测。

### 10. ComfyUI 视频帧重复驻留修复提案

**来源/日期**：[原始记录](https://github.com/Comfy-Org/ComfyUI/pull/17562)，2026-11-05；**证据及优先级**：D/P1。

**核心结论**：Get Video Components 拟避免解码帧持有两份；是后处理内存优化，不是视频生成提速。

**硬件适用性及限制**：4070、GB10 可测试；Mac 需确认。

**复现实验（环境、参数、基线、指标）**：576p/768p，5/10 秒 24fps 视频，比较 RSS/VRAM、帧 hash、提取墙钟。

**实测对比与应用判断**：峰值节省 MiB 尚无可靠数字。

### 11. ComfyUI ProRes/色度采样输出

**来源/日期**：[原始记录](https://github.com/Comfy-Org/ComfyUI/pull/17463)，2026-11-01；**证据及优先级**：D/P2。

**核心结论**：视频输出格式与色度采样能力变化，主要影响编码质量/体积，PR 状态需核对。

**硬件适用性及限制**：三平台取决于 FFmpeg 编译及编码器。

**复现实验（环境、参数、基线、指标）**：同一视频导出 H264/ProRes，记录编码秒数、文件大小、RAM、颜色差异。

**实测对比与应用判断**：不代表模型生成加速。

## 四、统一实验命令与指标

```bash
# 独立目录构建，不覆盖现有 llama-server；模型路径需替换
git clone https://github.com/ggml-org/llama.cpp.git llama-weekly-20261106
cd llama-weekly-20261106
git checkout v0.9.0
cmake -S . -B build -DGGML_CUDA=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 8
./build/bin/llama-bench -m /models/Qwen3.8-27B-IQ4_XS.gguf -ngl 999 -fa 1 -p 512 -n 128 -r 5
./build/bin/llama-server -m /models/Qwen3.8-27B-IQ4_XS.gguf -ngl 999 -c 6144 -fa on -b 2048 -ub 512 --cache-type-k q8_0 --cache-type-v q8_0 --host 127.0.0.1 --port 8081
nvidia-smi
```

以上是建议命令，不是已经执行的测试；先以对应版本 --help 核对选项。所有 A/B 固定 commit、GGUF SHA256、seed、采样、context、batch、ubatch、prompt 与输出长度，预热后重复至少 3 次。记录 pp/tg、aggregate tok/s、TTFT、p50/p95、VRAM/RAM、OOM、正确性和错误率。

**图片/视频生成专项**：本周没有足够可靠的 4070/GB10/Mac 同条件新模型生成实测。后续记录模型及许可证、分辨率、steps、seed、fps、frames、**视频内容时长**、**真实生成墙钟耗时**、峰值 VRAM/RAM、offload、去噪/VAE/编码分段耗时、输出质量；不把编码或解码加速误报为完整生成加速。没有数据则 NA。

## 六、最值得复现的三个实验

1. **P0 4070 llama.cpp v0.9.0 回归**：旧稳定版本 vs 新 tag，c6144/7168，pp512/2048，tg128/256，并发 1/2。收益：确认兼容性与潜在性能变化（未知）；风险：VRAM 已接近上限、SSE/API 行为变化。
2. **P0 4070/GB10 多模态服务恢复测试**：重复图像请求、取消长 embedding，再发短请求。收益：识别 /health 正常但请求失败的风险；风险：测试服务可能卡死，应独立端口。
3. **P1 GB10 MTP 与 MXFP4 隔离测试**：先确认架构和模型支持、backend ops 正确性，再测 4K/16K、1/2 并发、接受率、TTFT、tg、RSS。收益：判断是否值得等待 PR 合并；风险：开放 PR 不稳定、可能无收益。
