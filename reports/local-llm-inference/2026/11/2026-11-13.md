## 一、执行摘要与历史基线

本期找到 9 项有明确日期与源码的新增工程线索，主要集中在 MoE prefill、CUDA 少 token 内核、调度内存复用、投机解码确定性和 Agent API。并非 9 项均已合并或拥有可靠端到端测试；不为凑满 12 项重复旧内容。图片/视频生成、Mac Metal 性能和新 Qwen 量化本周没有足够可靠的可比新数据。

历史基线（非本周实测）：RTX 4070 Ti Super 16GB + Ubuntu 22.04，Qwen3.8-27B IQ4_XS GGUF，-ngl 999，-c 6144/7168，-fa on，-b 2048，K/V q8_0；pp 228–240 tok/s、tg 34.1–34.5 tok/s、VRAM 约 14.7GB，8192 context 曾 OOM。GB10 128GB 为 ARM64 CUDA；Mac Apple Silicon 仅作兼容性分析。

## 三、逐项研究

### 1. MoE layer-first prefill

**来源与日期**：[上游 PR](https://github.com/ggml-org/llama.cpp/pull/32082)，2026-11-11。**状态/优先级**：已关闭未合并；P1 GB10。

**核心结论、实测与限制**：改为按层优先处理 prefill，减少 MoE expert 重复搬运；作者在 QFN 特定测试声称 prefill 约 2×、PCIe 搬运约减至 1/4，decode 不变。GB10 统一内存机制不同，不能外推。 未提供可迁移至 4070/GB10/Mac 的同机端到端性能数字时记 NA。4070 当前 dense 27B 不能用于验证 MoE 特定优化；Apple Metal 不能运行 CUDA 专用内核。

**复现实验（环境、基线、参数、指标）**：MoE GGUF；主线与 PR worktree；prompt 2048/8192、ubatch 512/2048/4096，记录 pp/tg、专家搬运、RSS/VRAM、输出正确性。 每组至少 3 次，固定模型 hash、commit、采样与负载。**应用判断**：P1 GB10；开放 PR 不直接进入生产。

### 2. MoE cache 去同步路径

**核心结论、实测与限制**：作者称 Linux CUDA 特定测试约 10% 改善，尚非 GB10 或 4070 实测；dense 模型不适用。 未提供可迁移至 4070/GB10/Mac 的同机端到端性能数字时记 NA。4070 当前 dense 27B 不能用于验证 MoE 特定优化；Apple Metal 不能运行 CUDA 专用内核。

### 3. CUDA MoE MMQ 空 tile 越界读取修复

**来源与日期**：[上游 PR](https://github.com/ggml-org/llama.cpp/pull/32067)，2026-11-12。**状态/优先级**：已合并；P0 正确性。

**核心结论、实测与限制**：在无输出行的 MoE tile 提前返回，避免 fixup kernel 越界读取。主要是内存安全修复，不能声称整体提速。 未提供可迁移至 4070/GB10/Mac 的同机端到端性能数字时记 NA。4070 当前 dense 27B 不能用于验证 MoE 特定优化；Apple Metal 不能运行 CUDA 专用内核。

**复现实验（环境、基线、参数、指标）**：CUDA MoE 模型构造空专家路由，旧新版本运行 test-backend-ops 与 compute-sanitizer memcheck，测错误数、输出 hash、pp/tg。 每组至少 3 次，固定模型 hash、commit、采样与负载。**应用判断**：P0 正确性；开放 PR 不直接进入生产。

### 4. 少 token MoE few-row MMQ

## 四、统一复现实验环境

```bash
git clone https://github.com/ggml-org/llama.cpp.git llama-weekly-20261113
cd llama-weekly-20261113
git rev-parse HEAD
cmake -S . -B build -DGGML_CUDA=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 8
./build/bin/llama-bench -m /models/Qwen3.8-27B-IQ4_XS.gguf -ngl 999 -p 512 -n 128 -r 5
./build/bin/llama-server -m /models/Qwen3.8-27B-IQ4_XS.gguf -ngl 999 -c 6144 -fa on -b 2048 -ub 512 --cache-type-k q8_0 --cache-type-v q8_0 --host 127.0.0.1 --port 8081
nvidia-smi
```

模型路径为占位符；先检查对应 commit 的 --help，不能假定 PR 参数已进入主线。MoE 专项使用独立合法 GGUF，不能用 dense 27B 替代。GB10 原生 ARM64 CUDA 构建，Mac Metal 构建。统一记录 pp/tg、TTFT、aggregate tok/s、QPS、p50/p95/p99、VRAM/RAM、OOM、正确率和输出一致性。论文或作者局部 benchmark 不等于本机实测。

## 五、生成模型、长上下文与量化的数据缺口

**本周缺少可靠的新开源图片/视频生成模型本地部署实测**，无法同时核实模型权重与许可证、4070/GB10/Mac 的可运行性、分辨率、steps、视频内容时长、单图/单视频生成墙钟耗时、峰值显存、offload 和质量。因此全部记 NA，不虚构模型与速度。后续区分去噪、VAE、编码/解码和完整生成耗时。新 Qwen GGUF 量化对现有 IQ4_XS 的同机质量/速度对比、KV cache 新论文在 llama.cpp 中的可复现性能，以及 Apple Metal 长上下文同机基准亦不足；本期不重复旧论文。

## 七、最值得复现的三个实验

1. **P0 4070 CUDA/Server 正确性回归（半天）**：旧稳定版与包含已合并修复的新构建，dense 27B c6144/7168，pp512/2048、tg128/256、并发1/2，额外验证 Responses JSON schema 与 SSE。**预期收益**：确认升级兼容性；速度收益未知。**风险**：VRAM 接近上限，必须隔离端口并保留回滚。
2. **P1 GB10 MoE cache + few-row（约一天）**：MoE GGUF，cache 0/1024/4096 MiB，2/4/8/16 token，prefill 2048/8192；隔离 PR 分支比较同步次数、tg、TTFT、显存、输出一致性。**预期收益**：检验作者的少 token/同步优化是否适合 GB10。**风险**：未合并代码、统一内存差异、正确性回退。
3. **P1 投机解码 batch invariance（半天）**：固定温度0/seed，ubatch 128/512/2048、draft on/off，100 prompts，测 token 一致率、接受率、tg、TTFT。**预期收益**：明确评测与 Agent 工具调用可重复性。**风险**：确定性可能牺牲吞吐。
