## 一、本期摘要

本周最值得投入工程验证的变化有三类：第一，OpenCode 2.1.0 明确调整公开 SDK、HTTP 事件和插件契约，升级不再只是配置迁移；第二，OpenCode 2.1.4 补齐 MCP elicitation 人机交互、客户端 MCP 接入和后台压缩；第三，Codex 0.164.0 与 Claude Code 2.1.304–310 将企业 MCP 认证、权限审计、幂等重试、沙箱隔离与恢复语义进一步前移到运行时。

**对内部 Engineering Agent 的判断：** 应把“协议兼容 + 权限决策 + 可恢复执行”作为共同基础设施，优先于继续堆叠单点工具数量。Cursor 官方更新页在本窗口内未见晚于 10 月 16 日的新公告，因此本期不重复上周的 Environments API 和 Origin Marketplace。

## 三、重要更新

### 1. OpenCode 2.1.0：SDK、HTTP 事件与插件契约变更

**事实（2026-10-20）：** 官方将 Provider replay data 的多个旧字段（如文本/推理部分的 `state`、消息的 `providerState`、结果的 `resultState`）统一为 `native`；工具调用和结果共用 `tool.native`。凭据写入由 `configuration` 改为 `metadata`；压缩记录使用 `metadata.keepID`，原 `session.compacted` 事件被移除。历史会话仍可通过兼容解码器读取，但公开写入契约需更新。

**技术/产品影响：** 基于 OpenCode 的二次封装若直接消费 SDK 类型、HTTP 事件、插件回调或会话重放数据，可能出现编译成功但状态映射丢失。需要把“存量数据可读”与“新接口可写”分开验证。

**待验证：** 对比 2.0.x 与 2.1.x 的事件 JSON Schema；验证 tool-call/result 的 native 合并、同 provider/model 重放、压缩前后历史一致性、凭据导入和旧插件兼容。建议保留契约回归样本和回滚开关。

来源：https://opencode.ai/changelog （v2.1.0）
标签：#OpenCode #SDK #Migration #SessionReplay；**P0**。

### 2. OpenCode 2.1.4：MCP elicitation 从“等待超时”变为可交互

**事实（2026-10-23）：** MCP 工具调用触发的 elicitation 表单现在可以在 Desktop/Web 显示，支持文本、数字、选项、多选、布尔及 URL 请求；SDK 增加实验性 `connectClientMcp()`，可通过客户端 MCP WebSocket transport 托管工具。并修复 MCP OAuth 回调、远程 MCP idle timeout、初次 reconciliation 重复注册，以及非根对象 output schema 的兼容问题。

**技术/产品影响：** MCP 不再只是无状态 Tool Calling，工具执行过程中可能出现人机补充输入。客户端工具托管也会引入连接生命周期和权限信任边界。对企业网关应明确 elicitation 谁来展示、谁来批准、超时如何取消。

**待验证：** 用本地 MCP Server 模拟多种表单、无用户在线、拒绝、取消、超时和重复回调；验证桌面、Web、无头 Agent 的行为差异，检查工具调用 ID 与审批日志关联。

来源：https://opencode.ai/changelog （v2.1.4）
标签：#MCP #Elicitation #WebSocket #Approval；**P0**。

### 3. OpenCode 2.1.4：后台压缩与上下文溢出回退

**事实（2026-10-23）：** 新增实验配置 `experimental.background_compaction`，在接近阈值时提前准备摘要；未被使用的摘要仍会产生 token 成本。Provider context 超限时先缩短较旧的工具输出与交换记录；增加 `opencode debug heap-dump [--server <url>]` 便于定位运行时内存问题。

**技术/产品影响：** 上下文压缩可以与主任务并行，但带来额外 token 开销和摘要版本竞争。不能仅看压缩是否减少 token，应同时评估任务正确率与关键约束保留情况。

**待验证：** 同一长任务比较默认压缩与后台压缩的 TTFT、总 token、峰值内存、任务成功率；注入“摘要准备完成前任务内容改变”的竞态；检查失败压缩后是否保留原始历史。

来源：https://opencode.ai/changelog （v2.1.4）
标签：#ContextCompaction #Latency #Memory；**P1**。

### 4. OpenCode 2.1.2–2.1.3：并发执行正确性与运行时安全

**事实（2026-10-21～22）：** 2.1.2 修复 Code Mode 异步任务在语句中途交错、导致写入丢失的问题，同时保留并发工具调用；2.1.3 将内置 Bun 升至 1.4.4，包含 Brotli、TLS、HTTP/1.1/2/3、WebSocket 与 fetch 相关安全修复，并修复 V1 会话迁移和 `apply_patch` 到 `edit` 的权限迁移。

**技术/产品影响：** “并行调用成功返回”不等于“代码写入顺序正确”。若企业产品依赖 Code Mode 执行器，应将写入原子性、任务取消和同一工作树竞争纳入验收。

**待验证：** 并发执行多个写入与 shell 任务，检查语句级交错、文件最终状态、取消后残留；对比运行时升级前后 MCP 网络、代理及插件兼容性。

来源：https://opencode.ai/changelog （v2.1.2、v2.1.3）
标签：#CodeMode #Concurrency #Bun #Security；**P0**。

### 5. Codex CLI 0.164.0：企业 MCP 认证与凭据保护

**事实（2026-10-23，GitHub Release）：** 新增通过符合条件的 Codex 账号授权或独立登录认证企业 MCP 连接的能力，覆盖需要 client secret 的 OAuth 客户端；支持在部分远程 Bash 命令与 Zsh snapshot 会话中遮蔽凭据，包括自定义 provider 凭据。同时可通过 `/model` 和 `/permissions` 参数调整模型、推理力度、速度与权限档位。

**技术/产品影响：** MCP 认证开始与 Agent 身份、企业授权、远程命令执行深度整合。凭据“显示时掩码”不等同于端到端秘密隔离，仍需限制工具环境变量和输出泄露。

**待验证：** 多租户 OAuth grant 与 token 续期；凭据在 shell stdout/stderr、历史记录、trace 和快照中的暴露；权限档位切换后已排队工具是否继承新策略。

来源：https://github.com/openai/codex/releases/tag/rust-v0.164.0
标签：#Codex #EnterpriseMCP #OAuth #Secrets；**P0**。

### 6. Codex CLI 0.164.0：长任务恢复与审批状态一致性

**事实（2026-10-23）：** 修复压缩失败后遗留部分摘要、后台压缩失败导致 panic、恢复会话找不到压缩历史及丢失线程设置的问题；待审批选择完成后才继续排队提示；Windows HTTPS/WebSocket 代理支持 Negotiate/NTLM 挑战；还加强了 macOS 大小写变体元数据路径与可替换符号链接的沙箱检查。

**技术/产品影响：** 对无人值守长任务而言，恢复不仅要找回消息，还要找回线程级配置、权限状态和任务队列。代理兼容也影响企业网络中的部署可用性。

**待验证：** 人为制造压缩异常、重启与恢复、审批未完成时注入新指令；检查上下文和权限是否漂移；在企业代理下分别测试 HTTP、WebSocket、凭据协商。

来源：https://github.com/openai/codex/releases/tag/rust-v0.164.0
标签：#Recovery #Compaction #Approval #Proxy；**P1**。

### 7. Claude Code 2.1.304–305：ToolSearch 网关兼容回退与权限 Hook

**事实（2026-10-19～20，GitHub Release）：** 2.1.304 为 mod 的 `tool.check` 增加 `decider: "person"` 和 `e.isReadOnly`，便于强制由真人审批；2.1.305 修复 2.1.304 引入的回归：当 Vertex、Bedrock、兼容网关或 `--tools` 配置不接受 ToolSearch 时，请求改为不带该能力重试。另修复云端/SDK MCP Server 被同名本地配置替换，以及 Workflow resume 重复运行已完成的 `pipeline()`、`parallel()` Agent。

**技术/产品影响：** 动态工具发现属于可协商能力，网关不支持时必须有明确降级策略；但降级也可能改变上下文占用和工具可用性。强制真人审批与无人值守执行必须有可预期的失败路径。

**待验证：** 分别使用支持/拒绝 ToolSearch 的 OpenAI 兼容网关；测量 fallback 后的工具召回、token、成功率；验证人工审批不可用时是否 fail closed，恢复任务是否重复执行。

### 8. Claude Code 2.1.307：MCP 重试语义与安全事件可观测性

**事实（2026-10-21）：** 新增 `claude_code.safety_event` OpenTelemetry 事件，记录被权限规则、auto mode、安全检查、Hook 或沙箱阻止/提示/退回的工具调用；修复 HTTP MCP 连接中途关闭时工具调用重复发送的问题，现仅重试只读或幂等工具；修复 SDK MCP Server 最新工具列表未及时进入下一轮等问题。

**技术/产品影响：** 工具重试不能简单依赖 HTTP 连接状态，必须区分只读、幂等与有副作用操作。权限拒绝也应作为一等观测事件，而不是仅存在于交互日志。

**待验证：** 注入断线发生在“服务端已执行但响应丢失”之后；对转账式写操作/创建资源/查询分别检查是否重放；将 safety_event 与 tool_call_id、审批主体、策略版本关联。

**事实（2026-10-22～24，北京时间）：** 2.1.309 修复多种沙箱/权限绕过边界，包括 shell 启动文件在沙箱外运行、符号链接真实路径下 denyWrite 未生效、`--mcp-config` 文件可被修改、Worktree 隔离下部分命令绕过检查。2.1.310 修复 Windows 某些 Hook 环境下错误放行工具、MCP elicitation 在无交互会话中超时后错误重试；并为云端会话和 Remote Control 增加 Enterprise 自定义角色权限控制。

**技术/产品影响：** 目录白名单、路径匹配与 shell 解析的安全语义不能仅依赖字符串判断。远程控制与云端任务应被纳入 RBAC；无人值守任务必须避免无限等待无法回答的 elicitation。

**待验证：** 测试软链接、工作树、shell 初始化脚本、路径大小写及重定向绕过；检查远程会话权限矩阵；模拟无头 MCP elicitation 超时并确认不重复执行有副作用工具。

## 五、产品定位与架构启示

**定位：** 面向团队的 AI Engineering Agent 不应仅包装 Coding CLI，而应提供统一的任务生命周期：需求输入 → 任务分解 → 工具发现 → 权限审批 → 隔离执行 → 测试验证 → 代码审查 → 可追溯交付。

**建议划分六个模块：** (1) Tool Registry/Search 与协议能力协商；(2) Policy Engine/RBAC/人工审批；(3) Execution Sandbox/Worktree；(4) Task Journal/恢复与幂等控制；(5) Context Manager/压缩与历史重放；(6) Observability/审计事件与产物关联。尤其要将 MCP Tool 的“是否幂等、是否需要 elicitation、可否无头运行”作为注册元数据，而非执行失败后临时猜测。

## 六、研发优先级与可复现实验

| 优先级 | 建议实验 | 对照组与方法 | 观测指标 |
|---|---|---|---|
| P0 | OpenCode 2.0→2.1 契约迁移 | 固定样例回放两版本的 SDK/HTTP 事件和插件 Hook | 字段缺失、解析失败、重放成功率 |
| P0 | MCP 断线与幂等重试 | 读操作/写操作在执行后、响应前断线；模拟 elicitation | 重复副作用次数、恢复成功率、审批记录完整度 |
| P0 | ToolSearch 网关降级 | 支持 ToolSearch vs 拒绝 ToolSearch 的网关；对照全量工具 | Recall@3、任务成功率、token、P50/P95 |
| P0 | Sandbox/RBAC 边界 | symlink、shell 初始化、Worktree、远程角色矩阵 | 越权成功数（目标为0）、误拒绝率 |
| P1 | 后台压缩和任务恢复 | 长上下文任务，分别启用/关闭后台压缩并注入重启 | 成功率、总 token、首 token 延迟、恢复一致性 |

**最值得先做的两个实验：** 一是 OpenCode 2.1 契约回归，直接影响内部封装升级；二是 MCP ToolSearch + 断线/重试/elicitation 组合实验，可复用已有 42 工具渐进加载基准，检验真实生产稳定性。

3. Claude Code ToolSearch 降级是否带来工具召回下降；MCP 幂等重试与 safety_event 是否有可对接的开放语义。
4. Cursor 是否公布新的云端 Agent、环境 API、插件市场或跨仓库工程能力；没有官方新消息则不凑数。
