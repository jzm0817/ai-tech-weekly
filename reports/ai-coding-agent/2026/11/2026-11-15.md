## 二、重要更新与技术分析

### 1. OpenCode 2.3.0：子 Agent 默认后台执行

**发布日期与事实：** 2026-11-13。子 Agent 立即返回 session ID、后台继续执行并在空闲时汇报；未完成的后台工作会标识为仍在运行。新增实验性 MCP events、Shell 跨服务交接恢复、兼容模型的 freeform tool input。

**技术与产品影响：** 多 Agent 编排必须区分「子任务返回」「子任务空闲」「真正完成」，否则父任务可能提前验收；事件驱动的工具状态也值得关注。

**待验证事项：** 以两个子 Agent 并行修改不同 Worktree，测试中断、重启、后台 Shell 未结束时父任务是否错误完成；验证事件丢失及重放。

**优先级：** P0；**标签：** #OpenCode #Subagent #MCP。

**官方来源：** [发布记录](https://github.com/anomalyco/opencode/releases/tag/v2.3.0)。

### 2. OpenCode 2.3.0：mTLS 与本地模型发现

**发布日期与事实：** 2026-11-13。Provider 可配置客户端 TLS 证书与密钥以连接要求双向 TLS 的网关；Ollama、LM Studio、vLLM 模型发现请求等待上限延长至 15 秒，慢端点不再阻塞其他发现与配置刷新。

**技术与产品影响：** 对企业模型网关及本地 DGX/消费级 GPU 推理服务更友好，但证书文件权限和密钥泄露面需要独立控制。

**待验证事项：** 用双向 TLS 网关验证证书轮换、错误证书、密钥文件权限；模拟慢速 vLLM/Ollama，测试模型发现超时与其他 Provider 隔离。

**优先级：** P1；**标签：** #Gateway #mTLS #LocalLLM。

**官方来源：** [发布记录](https://github.com/anomalyco/opencode/releases/tag/v2.3.0)。

### 3. OpenCode 2.2.7：MCP 工具变更增量通知

**发布日期与事实：** 2026-11-10。MCP Server 连接、断开或工具变化时，Code Mode 向模型发送简短变更清单，而不是重复发送完整工具目录；并修复多客户端并发刷新远程 MCP OAuth Token 的登录失效问题。

**技术与产品影响：** 对渐进式工具发现非常关键：注册表更新、动态工具可见性与模型上下文增量通知可以拆开测量。

**待验证事项：** 在 42 工具集合中动态增加/删除工具，测量上下文 token 增量、工具正确调用率、并发 OAuth 刷新与重连一致性。

**优先级：** P0；**标签：** #ToolSearch #MCP #OAuth。

**官方来源：** [发布记录](https://github.com/anomalyco/opencode/releases/tag/v2.2.7)。

### 4. OpenCode 2.2.7：SDK 异步加载契约变化

**发布日期与事实：** 2026-11-10。`@opencode/ai` 移除 `ImageResponse.image`，改读 `response.images[0]`；`agent.list`、`integration.list`、`artifact.*` 等端点不再统一等待插件加载完毕，插件提供的条目需在对应 `*.updated` 事件后刷新。

**技术与产品影响：** 内部 OpenCode 二次封装若假设列表首次返回即完整，可能漏掉插件工具、Agent 或 Artifact；属于明确的兼容性风险。

**待验证事项：** 对比冷启动与插件延迟加载时的 SDK 返回值、事件顺序和列表刷新；全局搜索旧 `response.image` 调用。

**优先级：** P0；**标签：** #SDK #Plugin #BreakingChange。

**官方来源：** [发布记录](https://github.com/anomalyco/opencode/releases/tag/v2.2.7)。

### 5. Codex CLI 0.168.0：Provider 与会话状态解耦

**发布日期与事实：** 2026-11-13。新增终端模型 Provider 列表与默认 Provider 选择；新会话遵循新默认值，已存在会话恢复时继续使用原 Provider。App Server 文档补充自定义网关和云厂商配置。

**技术与产品影响：** 多模型网关接入不能只保存模型 ID，还需要把 Provider、认证和会话状态一同持久化，避免恢复时误切模型。

**待验证事项：** 在自建兼容网关和官方 Provider 间切换默认值，恢复历史会话检查 Provider、审批和模型设置是否一致。

**优先级：** P1；**标签：** #Codex #Provider #Session。

**官方来源：** [发布记录](https://github.com/openai/codex/releases/tag/rust-v0.168.0)。

### 6. Codex CLI 0.169.0：非可信目录执行隔离

**发布日期与事实：** 2026-11-13。`codex exec` 在不可信目录中即使使用 `--sandbox workspace-write` 仍禁用项目配置和 MCP Server；需要显式 `--trust` 才能保存信任。并修复中断回合和延迟取消误影响后续回合的问题。

**技术与产品影响：** 将目录信任与文件写入沙箱权限区分开，适合 CI 中处理外部 PR 或未知仓库；避免仅凭 workspace-write 意外启用项目内工具。

**待验证事项：** 在未信任仓库注入项目 MCP 配置与指令，验证 exec/review 默认拒绝；测试取消后新回合不被旧信号中断。

**优先级：** P0；**标签：** #Codex #Sandbox #Trust。

**官方来源：** [发布记录](https://github.com/openai/codex/releases/tag/rust-v0.169.0)。

### 7. Claude Code 2.1.321：模型上下文与缓存选择

**发布日期与事实：** 2026-11-10（北京时间）。官方发布 Claude Fable 5.2 支持 1M 上下文，并作为默认 Fable 模型；发布说明给出输入/输出及缓存读取价格。此为官方能力与定价声明，不代表任何本地性能测试。

**技术与产品影响：** 长上下文会改变工具结果保留、压缩阈值和缓存成本的权衡；但不宜因此取消上下文压缩与任务状态管理。

**待验证事项：** 在同一长代码库任务中比较不同上下文窗口的成功率、缓存读取比例、延迟与总成本。

**优先级：** P1；**标签：** #ClaudeCode #LongContext #Cost。

**官方来源：** [发布记录](https://github.com/anthropics/claude-code/releases/tag/v2.1.321)。

### 8. Claude Code 2.1.323–325：恢复、网关与安全修复

**发布日期与事实：** 2026-11-13—14（北京时间）。2.1.325 修复 zstd 压缩响应解码安全问题、第三方网关上下文超限后未触发压缩、非正常退出后恢复丢失近期回合，以及子 Agent 使用不同模型时文件/MCP 结果按主模型窗口计量的问题。

**技术与产品影响：** 与企业代理网关、混合模型子 Agent 和长期任务恢复直接相关；建议把压缩响应与异常退出纳入回归。

**待验证事项：** 测试截断/损坏压缩响应、网关上下文错误、异常退出后会话恢复、主子模型上下文窗口不同的工具大结果。

**优先级：** P0；**标签：** #ClaudeCode #Security #Compaction #Recovery。

**官方来源：** [发布记录](https://github.com/anthropics/claude-code/releases/tag/v2.1.325)。

## 四、产品定位与工程优先级

建议继续将内部产品定位为**可恢复、可审计、可验证交付的 Engineering Agent**，将 Agent Runtime 与模型能力解耦。以下是本周最值得投入的工程工作：

| 优先级 | 工作方向 | 验收标准 |
|---|---|---|
| P0 | 子 Agent 生命周期状态机 | 明确 queued/running/idle/waiting/completed/cancelled；父任务不提前验收 |
| P0 | MCP Tool Registry 增量一致性 | 连接变化、工具变更、重连后检索结果与真实工具定义一致 |
| P0 | OpenCode SDK/插件升级兼容 | 冷启动插件加载不丢 Agent/Tool；废弃字段可迁移 |
| P0 | 不可信仓库安全执行 | 未信任目录不自动加载项目 MCP/配置，显式信任可审计 |
| P1 | 多 Provider 与长上下文恢复 | 会话恢复模型不漂移、压缩失败有回退、成本可追踪 |

## 五、建议复现实验

**实验 A｜42 工具渐进加载 + MCP 动态变更：** 在现有检索实验上新增连接/断线/工具增删，比较全量目录注入与增量变更通知的 token、Recall@3、业务调用成功率和 P50/P95；同时验证 OAuth 并发刷新和工具定义版本。

**实验 B｜后台子 Agent 与任务终态：** 两个子 Agent 分别在独立 Worktree 执行编码和测试，插入慢 Shell、异常退出、重启、取消，记录父任务错误提前完成率、残留进程、恢复成功率及审计完整性。

**实验 C｜目录信任与网关恢复：** 对未知仓库运行 Codex exec，检查项目 MCP 不会加载；使用企业兼容网关模拟上下文超限、压缩响应损坏与连接中断，验证恢复行为。

上述为建议测试，不是已完成的本地实验。
