## 二、重要更新

### 1. OpenCode 2.2.6：共享 MCP 连接与启动可用性

**事实（11 月 6 日）：** MCP Server 可以启用连接池，在配置相同的项目间复用连接，以减少进程数和启动时间。模型调用前也会短暂等待正在连接的 MCP Server（最多约 2 秒），改善首轮工具可见性；修复本地 MCP 工作目录、旧式 stdio 服务等兼容问题。

**产品影响：** Tool Registry 的“工具已注册”与“工具已就绪”需要分开建模；共享连接则引入跨项目隔离与会话生命周期问题。

**待验证：** 在 42 工具实验中比较共享/独立连接的冷启动、P50、工具可见率、断线恢复及跨项目凭据隔离。

**来源：** [OpenCode 2.2.6 官方 Changelog](https://opencode.ai/changelog)；标签：#OpenCode #MCP #ToolSearch。

### 2. OpenCode 2.2.6：非交互式执行和 Worktree

**事实（11 月 6 日）：** `opencode run -w` 可以在新 Git Worktree 中启动，`--worktree=<name>` 可指定名称；`--archived` 将脚本或 CI 会话从常规收件箱隐藏。非交互式 `opencode run` 会等待由提示启动的后台 Shell、子 Agent 和图像作业完成，并提供 `background_wait` 事件；SIGTERM 现在会取消会话和后台作业并以 143 退出。官方明确提醒：没有默认等待上限，长期运行的开发服务器可能导致 CI 一直挂起。

**产品影响：** 自动化任务需要显式的作业生命周期、超时和清理策略，不能以“主模型回复结束”作为任务完成条件。

**待验证：** CI 超时、SIGTERM、孤儿子进程、Worktree 清理、后台作业永久运行、同一仓库并行修改的正确性。

**来源：** [OpenCode Changelog](https://opencode.ai/changelog)；标签：#Worktree #CI #Cancellation #Subagent。

### 3. OpenCode 2.2.6：网络与服务端安全边界

**事实（11 月 6 日）：** 服务端文件与媒体读取改为受限下载，并阻止不允许的来源对 `/api/*` 的跨站请求；WebFetch 和 Code Mode fetch 拒绝带凭据的 URL，重定向逐跳检查 WebFetch 权限；跨项目的 `session_move` 需要外部目录权限。

**产品影响：** 工具权限应覆盖 URL 规范化、重定向、服务端来源和跨目录操作，而不只是工具名称白名单。

**待验证：** 带 userinfo 的 URL、重定向到受限域名、跨源 API 调用、符号链接与项目迁移的越权场景。

**来源：** [OpenCode Changelog](https://opencode.ai/changelog)；标签：#Security #WebFetch #Policy。

### 4. OpenCode 2.2.6：插件 UI 与后台作业观测

**事实（11 月 6 日）：** GUI 插件可以扩展主题、代码块操作及原生设置/菜单组件；SDK 新增实验性 `client.experimental.job.list()`，可按会话、子孙关系、类型、状态查询后台 Shell、子 Agent 和图像作业。服务端嵌入者也可提供自定义 `fetch` 实现。

**产品影响：** 内部 Engineering Agent 可以将后台作业列表纳入任务面板，但实验 API 不宜直接作为稳定业务契约。

**待验证：** 插件升级兼容、作业状态与事件一致性、作业归属、权限隔离、自定义网络传输的审计。

**来源：** [OpenCode Changelog](https://opencode.ai/changelog)；标签：#Plugin #SDK #Observability。

### 5. Codex 0.167.0：多后端与 Agent 控制中心

**事实（11 月 6 日，GitHub Release）：** `codex agents --no-daemon` 可打开 Agent 控制中心，显示未读结果；终端会话选择器支持在已连接后端间切换并保留草稿。切换 Provider 后仍可查看已保存对话；无法恢复的对话可读取历史并整理为新对话提示。

**产品影响：** 多 Agent 工作台的关键是会话与后端解耦，尤其要区分“历史可读”和“执行状态可恢复”。

**待验证：** 切换后端时的会话标识、草稿保真、历史回放和失败恢复路径。

**来源：** [Codex 0.167.0 官方 Release](https://github.com/openai/codex/releases/tag/rust-v0.167.0)；标签：#Codex #MultiBackend #Session。

### 6. Codex 0.167.0：网络审批与上下文恢复

**事实（11 月 6 日）：** 并发请求同一端点时网络审批改为顺序提示，网络请求结束后审批弹窗会关闭；macOS/Windows 系统代理可在实验设置中选择启用。自动上下文压缩计入失败响应保留输出及缺失 token 使用量的响应；App Server 文档补充托管网络约束和需要新人工审批的规则。

**产品影响：** 网络权限与 token 预算都是 Agent Runtime 状态，不能仅根据成功请求统计或静态域名白名单推断。

**待验证：** 并发网络审批、代理切换、失败响应后的压缩阈值、恢复会话的审批边界。

**来源：** [Codex 0.167.0 官方 Release](https://github.com/openai/codex/releases/tag/rust-v0.167.0)；标签：#NetworkPolicy #Compaction #Proxy。

### 7. Claude Code 2.1.318：配置写入与会话一致性

**事实（11 月 4 日）：** 修复 `--continue` 在工具调用异常重试耗尽后丢失前文的回归；`claude mcp add/remove` 现在等待配置文件锁或报错，而不是无锁写入；共享网络主目录配置保存失败时不再虚报成功。认证状态增加登录过期时间与临近到期提示，另增加跨 AWS 账户角色及开发者成本归属能力。

**产品影响：** MCP 配置和凭据属于共享可变状态，需要原子更新、错误可见性和审计；这与周报 GitHub 归档的“提交后读回验证”是同一类可靠性问题。

**待验证：** 两个终端并发修改 MCP 配置、NFS 只读或锁冲突、登录刷新、异常工具调用后的继续会话。

**来源：** [Claude Code 官方 Releases](https://github.com/anthropics/claude-code/releases/tag/v2.1.318)；标签：#MCP #ConfigLock #Recovery #Credentials。

### 8. Cursor：Live Apps 与实时语音协作

**事实（11 月 5—6 日）：** Cursor 的 Cloud Agent 可以从需求生成可分享的实时应用，包括按需建立 Postgres、SSO 认证和托管；发布前有确定性及 Agent 安全检查，需用户明确发布，团队管理员可管理应用、密钥与发布策略。次日上线与 Agent 的实时双向语音交互，覆盖 Agents Window、IDE、Web 和 iOS，可在编码进行中询问进度与 Diff。

**产品影响：** 产品价值从“交付代码”延伸到“交付可访问、可管控的业务应用”；语音更偏交互体验，Live Apps 对需求到交付自动化的架构意义更大。

**待验证：** 应用密钥与数据库权限、发布审批、回滚、成本、跨仓库复现；语音模式下的操作确认与审计一致性。

**来源：** [Cursor：Build Live Apps（11 月 5 日）](https://cursor.com/changelog)；[Cursor：Voice Chat with Agents（11 月 6 日）](https://cursor.com/changelog)；标签：#Cursor #CloudAgent #Deployment #Voice。

## 四、产品定位与规划建议

**定位：** 内部 Engineering Agent 应优先构建可恢复、可审计的执行系统，而不是简单扩充工具数。推荐将任务生命周期、MCP 连接管理、Policy Engine、Worktree 隔离、作业状态与产物发布门禁作为基础模块。

| 优先级 | 工程行动 | 验收点 |
|---|---|---|
| P0 | OpenCode 非交互式运行与 Worktree 压测 | SIGTERM、超时、后台作业清理无遗漏 |
| P0 | MCP 连接复用与工具发现 | 冷启动、Recall@3、跨项目隔离、重连恢复 |
| P0 | 网络与文件访问安全回归 | 重定向、跨源、跨目录均受策略约束 |
| P1 | Codex 多后端与会话恢复 | 历史可读、审批状态不漂移 |
| P1 | Live Apps 发布链路 PoC | 需求→应用→安全检查→人工发布→回滚 |

**最值得复现的实验：** （1）用现有 42 工具集合对比独立 MCP 连接与连接池，加入重连和跨项目访问测试；（2）让 OpenCode 在 CI 中启动后台子 Agent 和长期 Shell 作业，模拟超时/SIGTERM，验证执行与清理；（3）设计一个内部小型 Web 应用，测量需求到可验收部署的人工干预次数和发布风险。以上为建议，非本地实测。
