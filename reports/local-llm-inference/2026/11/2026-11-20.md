# 本地 LLM 推理研究深度简报｜2026-11-20

> 统计窗口：2026-11-13～20（北京时间）。证据 A=官方已合并/发布，B=作者特定实验，D=未合并提案。P0=优先验证、P1=条件验证、P2=研究储备。**本期没有在用户设备上运行实验，所有未测性能为 NA。**

## 一、摘要与硬件基线

本周值得关注的是 **MiSTiQ 极低比特 KV 论文、CUDA MoE 重复 expert ID 修复、IQ2 量化制作缓存优化，以及 server realtime 休眠修复**。另补充上周截止日发布的 llama.cpp v1.0.0 版本信息，明确它是跨期核实，不冒充本周全新成果。作者的 IQ2 量化制作加速与模型推理速度不是同一指标；MiSTiQ 尚无 llama.cpp 即插即用实现。

历史基线（不是本期测量）：RTX 4070 Ti Super 16GB，Ubuntu 22.04，Qwen3.8-27B-IQ4_XS GGUF，-ngl 999、-c 6144/7168、-fa on、-b 2048、K/V q8_0；pp 约 228–240 tok/s、tg 约 34.1–34.5 tok/s、显存约 14.7GB，c8192 曾 OOM。DGX Spark/GB10 128GB 采用 ARM64 CUDA；Mac Apple Silicon 需要独立 Metal 复现，不能套用 CUDA 性能。

## 三、逐项研究

### 1. MiSTiQ 极低比特 KV Cache

**来源与日期**：[原始材料](https://arxiv.org/abs/2611.21216)，2026-11-16。**证据/优先级**：论文作者实验；P1 研究。

**核心结论**：用 trellis 量化结合 microscaling/MX 格式，使 KV 在约 1.25 effective bit/element 下仍保持较好的困惑度、GSM8K 和 LongBench 表现；作者在 Llama3/Qwen3 上比较多种基线。1.25 bit 不是现成 llama.cpp 参数，也不能据此宣称 4070 提速。

**硬件适用性与限制**：4070 16GB 有长上下文显存潜力，但需要新编码/attention kernel；GB10 适合实验；Mac Metal 缺直接实现。

**可复现实验（环境、命令/参数、基线、指标）**：以论文代码和 Qwen3 小模型为起点，对照 FP16/q8_0/q4_0 KV，4K/8K/16K、batch1/2，记录有效 bit、峰值 VRAM、pp/tg、LongBench/GSM8K、编码耗时；再评估能否移植 GGUF。

**实测对比及是否应用**：作者质量对比，暂无三平台同机吞吐；暂不替换现有 q8_0。

### 2. llama.cpp v1.0.0 稳定版本里程碑与接口变化

**来源与日期**：[原始材料](https://github.com/ggml-org/llama.cpp/releases/tag/v1.0.0)，2026-11-13（上期截止日发布，本期补充核验）。**证据/优先级**：官方发行说明；P0。

**核心结论**：移除旧 C API，NextN API 正式进入 llama.h，增加 OCP FP8 KV、MoE expert cache CPU share、外部 PLE shards、部分视觉和 TTS 支持，并加强 server 安全。属于版本基线信息，不把上期已经提到的 TTS/缓存功能重复计算为本期新成果。

**硬件适用性与限制**：4070 CUDA 关注 KV 类型与显存；GB10 关注 MoE cache 和 ARM64；Mac Metal 关注构建/API 兼容；对现有 Java OpenAI 兼容 API 调用影响通常小于直接链接 C API 的应用。

**可复现实验（环境、命令/参数、基线、指标）**：固定旧版 SHA 与 v1.0.0 tag，编译两套；Qwen 27B c6144/7168，pp512/2048、tg128/256、并发1/2；比较 VRAM、TTFT、p95、JSON schema、SSE、tool_calls、slot 恢复。

**实测对比及是否应用**：发行说明不是本机性能实测；优先回归，不直接升级生产。

### 3. CUDA MoE 重复 expert ID 正确性支持

**来源与日期**：[原始材料](https://github.com/ggml-org/llama.cpp/pull/32505)，2026-11-19。**证据/优先级**：已合并，作者测试；P0 GB10。

**核心结论**：修复 MoE 重复专家 ID 的 CUDA 处理，重写 mmid helper；作者提供 GraniteMoE 在 AMD 卡上的 pp4096 小幅提升数据（例如 MI60 854.35→859.02 tok/s，非 NVIDIA 实测）。核心价值是正确性，不是大幅提速。

**硬件适用性与限制**：GB10 的 MoE GGUF 优先；4070 仅跑 MoE 时受益；dense 27B 无关，Mac Metal 不使用 CUDA 实现。

**可复现实验（环境、命令/参数、基线、指标）**：选择能产生重复 expert ID 的 MoE 模型/合成输入，合并前后 test-backend-ops + 输出逐 token 比对，ubatch16/128/512、pp4096/tg256；记录错误率、GPU memcheck、VRAM、pp/tg。

**实测对比及是否应用**：上游 AMD 特定数据，GB10/4070 数值 NA；随稳定更新纳入。

### 4. IQ2 量化制作缓存优化

**来源与日期**：[原始材料](https://github.com/ggml-org/llama.cpp/pull/31910)，2026-11-19。**证据/优先级**：已合并，作者实测；P1。

**核心结论**：量化器缓存重复 codebook 候选模式，减少制作 IQ2 GGUF 的计算；作者在 Framework 32 线程、Qwen3.6-35B-A3B 测得 IQ2_XS 量化制作 3.04×、IQ2_S 2.99×、IQ2_XXS 2.08×、IQ2_M 1.46×。**这是离线量化制作加速，不是推理 tok/s 提升**。

**硬件适用性与限制**：与 4070/GB10/Mac 的推理 GPU 基本无关，量化工作站 CPU/内存更重要；现有 IQ4_XS 不直接受益。

**可复现实验（环境、命令/参数、基线、指标）**：同原始模型、imatrix、IQ2 类型，旧新 llama-quantize，记录制作墙钟、RSS、CPU、文件 hash、模型困惑度和最终 gguf 大小；固定线程 16/32。

**实测对比及是否应用**：作者实测限制作阶段；若自行制作 IQ2 值得采用，生产推理优先级低。

### 5. CPU/CUDA BF16 RoPE 与 SET_ROWS

**来源与日期**：[原始材料](https://github.com/ggml-org/llama.cpp/pull/32387)，2026-11-19。**证据/优先级**：已合并；P1。

**核心结论**：增加 BF16 张量在 RoPE 和 SET_ROWS 运算上的支持；重点是模型/算子兼容性，不等于现有 Qwen GGUF 推理提速。

**硬件适用性与限制**：4070/GB10 CUDA 可测试 BF16 路径；Mac Metal 不在此 PR 的 CPU/CUDA 范围；已有 IQ4_XS 路径不应假定受益。

**可复现实验（环境、命令/参数、基线、指标）**：backend ops 精度回归，BF16 与 FP16 参考，RoPE 长度 4K/16K、SET_ROWS 多 shape；记录最大误差、NaN、kernel 耗时、VRAM，再在兼容 BF16 模型测 pp/tg。

**实测对比及是否应用**：未找到同机端到端加速数值；按模型兼容需求启用。

### 6. Server realtime 睡眠状态崩溃修复

**来源与日期**：[原始材料](https://github.com/ggml-org/llama.cpp/pull/32567)，2026-11-18。**证据/优先级**：已合并；P0 Server 稳定性。

**核心结论**：修复服务休眠时客户端连接 /v1/realtime 可能崩溃的问题；与通用 /v1/chat/completions 性能不是一回事。

**硬件适用性与限制**：硬件无关，4070/GB10/Mac 若运行 realtime 或自动 sleep 则相关。

**可复现实验（环境、命令/参数、基线、指标）**：新旧构建独立端口，触发 sleep 后连接 /v1/realtime 100 次，记录崩溃率、health、RSS/VRAM、恢复首包延迟；再跑 chat completion 负载作为无回归对照。

**实测对比及是否应用**：无加速声称；稳定服务建议纳入回归。

### 7. CUDA MMA FlashAttention 列宽选择一致性

**来源与日期**：[原始材料](https://github.com/ggml-org/llama.cpp/pull/32626)，2026-11-19。**证据/优先级**：开放 PR；P1。

**核心结论**：针对 MMA FlashAttention 的 ncols2 选择一致性提出修正；具体性能与正确性改善仍待 PR 合并及基准核验，不能当成已上线优化。

**硬件适用性与限制**：4070 Ada 与 GB10 Blackwell CUDA 可能走不同 kernel；Mac Metal 不适用。

**可复现实验（环境、命令/参数、基线、指标）**：在隔离 PR 分支，FA on/off，c4096/7168、pp512/2048、tg128，backend ops 输出误差、Nsight kernel 时间、VRAM、端到端 pp/tg；遇 OOM 不扩容 4070。

**实测对比及是否应用**：未有可靠本机实测；不进入生产。

### 8. MCP / server 安全与默认端点回归

**来源与日期**：[原始材料](https://github.com/ggml-org/llama.cpp/releases/tag/v1.0.0)，2026-11-13（v1.0.0 中核实）。**证据/优先级**：官方发布；P0 Agent。

**核心结论**：v1.0.0 发行说明列出 SSRF、CORS、DNS rebinding 和 MCP tool cancellation 加固。作为本期安全回归补充，不重复计为新的独立论文或速度成果。

**硬件适用性与限制**：与 Java/Spring AI Agent、反向代理、局域网服务相关；GPU 类型无关。

**可复现实验（环境、命令/参数、基线、指标）**：测试允许/拒绝 URL、跨域 Origin、取消 MCP 工具调用、并发 1/4/8；记录 HTTP 状态、取消后资源回收、SSE、QPS、TTFT p95；在隔离网络执行，不对公网开放实验端口。

**实测对比及是否应用**：正确性/安全为主，吞吐影响 NA。

### 9. 多模态实时语音支持更新

**来源与日期**：[原始材料](https://github.com/ggml-org/llama.cpp/pull/32443)，2026-11-19。**证据/优先级**：上游合并记录；P2。

**核心结论**：新增 VoxCPM2 的多模态/语音模型支持，体现本地多模态服务扩展；并非图片或视频生成模型，也不代表 VLM 视觉准确率提升。

**硬件适用性与限制**：4070 需独立运行语音模型，避免与接近显存上限的 27B 同时常驻；GB10 更适合多模型；Mac 需核对后端算子。

**可复现实验（环境、命令/参数、基线、指标）**：模型许可与权重核实后，固定文本/音频 20 条，记录启动时间、RTF、首音频延迟、峰值 VRAM/RAM、输出质量，比较上游参考实现与 llama.cpp。

**实测对比及是否应用**：缺少三平台同机数据，按需研究。

## 四、统一实验方法与命令

先固定版本和模型 hash，实验构建单独端口，避免覆盖稳定服务。以下路径为示例；参数须以对应 tag 的 `--help` 为准。比较旧稳定版、v1.0.0 与本周特定修复 commit，**不能把 v1.0.0 当作包含 11-19 新合并 PR 的版本**。

```bash
git clone https://github.com/ggml-org/llama.cpp.git
cd llama.cpp
git checkout v1.0.0
git rev-parse HEAD
cmake -S . -B build -DGGML_CUDA=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 8
sha256sum /models/Qwen3.8-27B-IQ4_XS.gguf
./build/bin/llama-bench -m /models/Qwen3.8-27B-IQ4_XS.gguf -ngl 999 -p 512 -n 128 -r 5
./build/bin/llama-server -m /models/Qwen3.8-27B-IQ4_XS.gguf -ngl 999 -c 6144 -fa on -b 2048 -ub 512 --cache-type-k q8_0 --cache-type-v q8_0 --host 127.0.0.1 --port 8081
nvidia-smi
```

测试矩阵：c6144/7168、prompt 512/2048、generation 128/256、并发 1/2/4；每组预热并至少重复 5 次，记录 pp/tg、TTFT、QPS、aggregate tok/s、p50/p95/p99、显存峰值、RSS、OOM、错误率、输出质量与回归差异。GB10 原生 ARM64 CUDA 编译；Mac 用 Metal 编译。MoE 专项必须使用 MoE GGUF，不能拿 dense 27B 测 MoE kernel。

## 五、图片/视频生成、VLM 与 Mac 的数据缺口

本周没有核实到同时具备**本周明确日期、可合法获取权重、可复现三平台资源需求**的高质量新开源图片/视频生成部署报告。因此**不编造**分辨率、steps、视频内容时长、单图/单段视频生成墙钟耗时、峰值显存或生成质量；这些字段本期为 **NA**。今后按模型版本、许可证、分辨率、steps、帧率、视频内容时长、总墙钟、去噪/VAE 分段耗时、VRAM/RAM、offload 和质量记录。Mac Metal 本周没有可信的同机量化吞吐新数据；VLM 视觉识别/OCR 没有适合与上期直接对比的独立新基准。语音支持更新不混入图片/视频成果。

## 六、相对上期 2026-11-13 的变化

已读取 [上期报告](./2026-11-13.md) 做排重。上期的 layer-first MoE prefill（关闭未合并）、MoE cache 去同步、few-row MMQ、batch invariance、graph result 复用、Responses API schema、TTS endpoint、MCP 多模态工具结果均不重复列为本期新成果。**本期真正新增重点**是 11-16 MiSTiQ 论文、11-19 CUDA MoE 重复专家修复、11-19 IQ2 离线量化优化、11-18 realtime 休眠修复、11-19 BF16 算子与新 CUDA FA 提案。v1.0.0 在上期截止日发布，本期只补充完整发行信息与安全回归，不作为 11-20 新发布。

## 七、最值得复现的三个实验

**A｜4070 16GB v1.0.0 兼容与性能回归（P0，半天）**：同一 Qwen 27B IQ4_XS、c6144/7168、q8_0 KV、FA on，旧稳定版对 v1.0.0；加测 /v1/responses、chat、SSE、tool_calls、取消请求与安全配置。**预期收益**：明确可升级性、减少 API/显存回归风险，速度收益未知。**风险**：显存逼近上限，保持旧服务独立端口。

**B｜GB10 CUDA MoE 重复 expert ID 正确性（P0，半天）**：旧新 commit，同一 MoE GGUF、重复专家路由合成用例、ubatch 16/128/512、pp4096/tg256，检查 CUDA memcheck、token 一致率、VRAM、pp/tg。**预期收益**：避免特定 MoE 路由计算错误。**风险**：模型路由可能无法自然触发，需合成 backend ops。

**C｜KV 压缩与低比特量化研究（P1，1–2 天）**：GB10 先用 MiSTiQ 论文支持的小模型与公开测试集，和 FP16/q8_0/q4_0 比较 4K/8K/16K、batch1/2，测 LongBench/GSM8K、峰值 VRAM、编码耗时、pp/tg；4070 不直接改当前稳定 27B。**预期收益**：评估更长上下文的潜在空间。**风险**：论文实现与 llama.cpp 不兼容、压缩开销抵消收益、质量下降。
